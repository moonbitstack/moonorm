Guide

From a MoonBit struct to a table.

moonorm maps MoonBit types onto SQL at compile time. This guide runs end to end; every snippet compiles in a project that depends only on moonbitstack/moonorm.

spec model_test.mbt last passed this build version 0.11.1 compiler 0.1.x

1 · Install

Add the package and its driver seam:

moon add moonbitstack/moonorm
moon add moonbitstack/moondb

moonorm builds a query layer; moondb is the driver contract that a backend (sqlite, postgres, mysql) implements.

2 · Declare a model

A model pairs a MoonBit type with its columns. Each column carries its type and constraints; the mapping is checked as you write it.

struct Account {
  id : Int64?
  email : String
  balance : Double
  team_id : Int64
  status : String
  level : Int
}

let account = Model::new(
  "accounts",
  [
    column("id", BigIntType, primary_key=true, autoincrement=true),
    column("email", TextType, nullable=false, unique=true),
    column("balance", RealType),
    column("team_id", BigIntType, references=("teams", "id"), on_delete="SET NULL"),
    column("status", TextType, nullable=false, default="'active'"),
    column("level", IntType, checks=["level >= 0"]),
  ],
  r => { id: r.read(0), email: r.read(1), balance: r.read(2),
         team_id: r.read(3), status: r.read(4), level: r.read(5) },
  a => [
    ("id", match a.id { Some(v) => @moondb.Int64(v) | None => @moondb.Null }),
    ("email", @moondb.Text(a.email)),
    ("balance", @moondb.Double(a.balance)),
    ("team_id", @moondb.Int64(a.team_id)),
    ("status", @moondb.Text(a.status)),
    ("level", @moondb.Int(a.level)),
  ],
)

3 · Generate DDL

The same model yields correct DDL for every dialect — autoincrement keys, foreign keys, checks and defaults all rendered natively.

account.create_table_sql_for(Postgres)
// CREATE TABLE accounts (
//   id BIGSERIAL PRIMARY KEY, email TEXT NOT NULL UNIQUE,
//   balance DOUBLE PRECISION, team_id BIGINT
//     REFERENCES teams(id) ON DELETE SET NULL,
//   status TEXT NOT NULL DEFAULT 'active',
//   level INTEGER CHECK (level >= 0))

account.create_table_sql_for(Mysql)
// CREATE TABLE accounts ( ... ) ENGINE=InnoDB

account.create_table_sql_for(Sqlite)
// CREATE TABLE accounts (
//   id INTEGER PRIMARY KEY AUTOINCREMENT, ... )

Pass if_not_exists=true to prefix CREATE TABLE IF NOT EXISTS on every dialect.

4 · Build a query

A query is a MoonBit expression that compiles into dialect SQL. Values are bound, never spliced.

let q = account.select()
  .where_(fn(a) { a.email == "ada@x.io" })
  .order_by("level", Asc)
  .limit(10)
let (sql, params) = q.build()
// sql:  SELECT id, email, balance, team_id, status, level
//         FROM accounts WHERE email = ? ORDER BY level ASC LIMIT ?
// params: [Text("ada@x.io"), Int(10)]

5 · Insert a row

let ins = account.insert_of(rec)
let (sql, params) = ins.build_for(Postgres)
// INSERT INTO accounts (email, balance, team_id, status, level)
//   VALUES (?, ?, ?, ?, ?) RETURNING id
// params: [Text("ada@x.io"), Double(0.0), Int64(2), Text("active"), Int(1)]

6 · Migrate

Reflect a model against a live database, diff, and emit up/down migrations. Each change is labelled reversible.

let diff = Migrator::diff(existing_schema, account.create_table_sql_for(Postgres))
// → adds column `level INTEGER CHECK (level >= 0)`
// → reversible: yes (DROP COLUMN)

Dialects

The Dialect enum fixes the spelling of types, keys and placeholders. Choose it once per session; the seam renders the rest.

Dialectautoincrementplaceholder
SqliteINTEGER PRIMARY KEY AUTOINCREMENT?
PostgresBIGSERIAL PRIMARY KEY$1, $2, …
MysqlBIGINT AUTO_INCREMENT PRIMARY KEY?

Every example on this page is reproduced from a test that passes in this build. Where a snippet shows output, that output is the library's real result — not a hand-typed guess.
