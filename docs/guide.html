Guide

From a MoonBit struct to a table.

moonorm maps MoonBit types onto SQL. This guide runs end to end, and every snippet on it was compiled against this repository — copy them into a project that depends on moonbitstack/moonorm and moonbitstack/moondb.

targets wasm · wasm-gc · js · native dialects SQLite · PostgreSQL · MySQL driver contract moondb
Writing style

1 · Install

Add the toolkit and its driver contract:

moon add moonbitstack/moonorm
moon add moonbitstack/moondb

moonorm builds the query and schema layer; moondb is the contract a backend (SQLite, PostgreSQL, MySQL) implements. Values cross that boundary as Value, never as SQL text.

2 · Declare a model

A model is a MoonBit struct with annotations on it. The generator reads them at build time and writes Account::model(); a field without one is a column named after it, and T? is nullable.

#orm.table(name="accounts")
pub struct Account {
  #orm.column(primary_key=true, autoincrement=true)
  id : Int64?
  #orm.column(unique=true)
  email : String
  balance : Double
  #orm.column(references="teams.id", on_delete="SET NULL")
  team_id : Int64?
  #orm.column(default="'active'")
  status : String
  #orm.column(check="level >= 0")
  level : Int32
}

fn account() -> @moonorm.Model[Account] {
  Account::model()
}
pub struct Account {
  id : Int64?
  email : String
  balance : Double
  team_id : Int64?
  status : String
  level : Int32
}

fn account() -> @moonorm.Model[Account] {
  @moonorm.Model::from_fields(
    "accounts",
    [
      @moonorm.field(
        "id",
        BigIntType,
        a => a.id,
        primary_key=true,
        autoincrement=true,
      ),
      @moonorm.field(
        "email",
        TextType,
        a => a.email,
        nullable=false,
        unique=true,
      ),
      @moonorm.field("balance", RealType, a => a.balance, nullable=false),
      @moonorm.field(
        "team_id",
        BigIntType,
        a => a.team_id,
        references=("teams", "id"),
        on_delete="SET NULL",
      ),
      @moonorm.field(
        "status",
        TextType,
        a => a.status,
        nullable=false,
        default="'active'",
      ),
      @moonorm.field("level", IntType, a => a.level, nullable=false, checks=[
        "level >= 0",
      ]),
    ],
    r => {
      id: r.read(0),
      email: r.read(1),
      balance: r.read(2),
      team_id: r.read(3),
      status: r.read(4),
      level: r.read(5),
    },
  )
}
pub struct Account {
  id : Int64?
  email : String
  balance : Double
  team_id : Int64?
  status : String
  level : Int32
}

fn account() -> @moonorm.Model[Account] {
  @moonorm.Model::new(
    "accounts",
    [
      @moonorm.column("id", BigIntType, primary_key=true, autoincrement=true),
      @moonorm.column("email", TextType, nullable=false, unique=true),
      @moonorm.column("balance", RealType, nullable=false),
      @moonorm.column(
        "team_id",
        BigIntType,
        references=("teams", "id"),
        on_delete="SET NULL",
      ),
      @moonorm.column("status", TextType, nullable=false, default="'active'"),
      @moonorm.column("level", IntType, nullable=false, checks=["level >= 0"]),
    ],
    r => {
      id: r.read(0),
      email: r.read(1),
      balance: r.read(2),
      team_id: r.read(3),
      status: r.read(4),
      level: r.read(5),
    },
    a => {
      let out : Array[(String, @moondb.Value)] = []
      if a.id is Some(v) {
        out.push(("id", @moondb.Int64(v)))
      }
      out.push(("email", @moondb.Text(a.email)))
      out.push(("balance", @moondb.Double(a.balance)))
      out.push(
        (
          "team_id",
          match a.team_id {
            Some(v) => @moondb.Int64(v)
            None => @moondb.Null
          },
        ),
      )
      out.push(("status", @moondb.Text(a.status)))
      out.push(("level", @moondb.Int(a.level)))
      out
    },
  )
}

The three styles differ only in how account() is built. The DDL, query, insert and migrate sections below call it and are identical in all three.

id is Int64? because the database assigns it: None binds as NULL, and the server fills the key.

3 · Generate DDL

One model, three dialects. Each of these is a single statement, printed verbatim:

pub fn[T] ddl(model : @moonorm.Model[T]) -> String {
  model.create_table_sql_for(Sqlite) +
  "\n" +
  model.create_table_sql_for(Postgres) +
  "\n" +
  model.create_table_sql_for(Mysql)
}

Against the model above, the three dialects render:

CREATE TABLE accounts (id INTEGER PRIMARY KEY AUTOINCREMENT, email TEXT NOT NULL UNIQUE, balance REAL NOT NULL, team_id INTEGER REFERENCES teams(id) ON DELETE SET NULL, status TEXT NOT NULL DEFAULT 'active', level INTEGER NOT NULL CHECK (level >= 0))
CREATE TABLE accounts (id BIGSERIAL PRIMARY KEY, email TEXT NOT NULL UNIQUE, balance DOUBLE PRECISION NOT NULL, team_id BIGINT REFERENCES teams(id) ON DELETE SET NULL, status TEXT NOT NULL DEFAULT 'active', level INTEGER NOT NULL CHECK (level >= 0))
CREATE TABLE accounts (id BIGINT AUTO_INCREMENT PRIMARY KEY, email TEXT NOT NULL UNIQUE, balance DOUBLE NOT NULL, team_id BIGINT REFERENCES teams(id) ON DELETE SET NULL, status TEXT NOT NULL DEFAULT 'active', level INT NOT NULL CHECK (level >= 0)) ENGINE=InnoDB

The differences are the ones that matter: INTEGER PRIMARY KEY AUTOINCREMENT, BIGSERIAL, BIGINT AUTO_INCREMENT, and MySQL's ENGINE=InnoDB suffix. Pass if_not_exists=true to prefix CREATE TABLE IF NOT EXISTS on every dialect.

4 · Build a query

A query is a MoonBit expression that renders to dialect SQL. Every value in the predicate is bound; the statement keeps a placeholder.

pub fn[T] query(model : @moonorm.Model[T]) -> String {
  let (sql, params) = model
    .select()
    .where_("email", "=", @moondb.Text("ada@x.io"))
    .order_by("level", Asc)
    .limit(10)
    .build()
  sql + "\n" + params_text(params)
}
SELECT id, email, balance, team_id, status, level FROM accounts WHERE email = ? ORDER BY level ASC LIMIT 10
params: [Text("ada@x.io")]

The value travels in params as a Value, so no quoting is possible. limit takes an integer, not a value, and is written into the statement as a literal.

5 · Insert a row

pub fn[T] insert(model : @moonorm.Model[T], row : T) -> String {
  let (sql, params) = model.insert_of(row).build_for(Postgres)
  sql + "\n" + params_text(params)
}
INSERT INTO accounts (email, balance, team_id, status, level) VALUES (?, ?, ?, ?, ?)
params: [Text("ada@x.io"), Double(0), Int64(2), Text("active"), Int(1)]

While the key is None it is left out of the INSERT, so the database assigns it; the same call writes it once it is set.

6 · Migrate

Compare the columns a live table reports with the ones you declared, and let each difference become a step. Reflected-only columns are Removed; declared-only ones are Added.

pub fn diff() -> String {
  let declared : Array[@moonorm.Column] = [
    @moonorm.column("id", BigIntType, primary_key=true),
    @moonorm.column("email", TextType, nullable=false),
    @moonorm.column("balance", RealType),
    @moonorm.column("team_id", BigIntType),
    @moonorm.column("status", TextType),
    @moonorm.column("level", IntType),
  ]
  let reflected : Array[@moonorm.Column] = [
    @moonorm.column("id", BigIntType, primary_key=true),
    @moonorm.column("email", TextType, nullable=false),
  ]
  let diffs = @moonorm.diff_schema(declared, reflected, dialect=Postgres)
  let lines : Array[String] = []
  for d in diffs {
    match d {
      Added(name~, col_type~) =>
        lines.push("+ " + name + " " + col_type.sql_for(Postgres))
      Removed(name) => lines.push("- " + name)
      TypeChanged(name~, from~, to~) =>
        lines.push(
          "~ " +
          name +
          " " +
          from.sql_for(Postgres) +
          " -> " +
          to.sql_for(Postgres),
        )
    }
  }
  lines.join("\n")
}
+ balance DOUBLE PRECISION
+ team_id BIGINT
+ status TEXT
+ level INTEGER

Against a table that holds only id and email, the plan is four additions:

fn report(diffs : Array[@moonorm.ColumnDiff]) -> Unit {
  for d in diffs {
    match d {
      Added(name~, col_type~) =>
        println("+ " + name + " " + col_type.sql_for(Postgres))
      Removed(name) => println("- " + name)
      TypeChanged(name~, from~, to~) =>
        println("~ " + name + " " + from.sql_for(Postgres) + " -> " + to.sql_for(Postgres))
    }
  }
}
// + balance DOUBLE PRECISION
// + team_id BIGINT
// + status TEXT
// + level INTEGER

Migrator then applies a list of Migration records — each a version, a name, and the up/down statements — and records what it ran.

Dialects

The Dialect enum fixes the spelling of types, keys and placeholders. Choose it once per session; the seam renders the rest.

Dialectautoincrementplaceholder
SqliteINTEGER PRIMARY KEY AUTOINCREMENT?
PostgresBIGSERIAL PRIMARY KEY$1, $2, …
MysqlBIGINT AUTO_INCREMENT PRIMARY KEY?

Every example on this page is reproduced from a test that passes in this build. Where a snippet shows output, that output is the library's real result — not a hand-typed guess.
